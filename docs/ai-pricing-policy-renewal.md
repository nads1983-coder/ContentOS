# AI pricing review runbook

The pricing policy is a bounded review of provider rates, not the monthly funding approval. It expires at 00:00 UTC on 19 December 2026. Requests during the final seven days emit `AI pricing policy requires review before expiry` in server logs. This warning requires an operator to monitor logs; it is not an external alert and cannot warn during periods with no requests. Schedule a review before 12 December.

Before renewal, check the current provider prices and model availability, exchange-rate contingency, payload/token bounds, reserved and actual spending, and compare them with the rates in `lib/ai-cost.ts`. Review all supported image models, including shutdown restrictions. If bounds remain conservative, update the policy version and expiry and run `node --test tests/commercial-cost.test.mjs` and the disposable PostgreSQL ledger suite. Submit a reviewed deployment; expiry does not renew automatically. If pricing cannot be verified, keep the existing fail-closed behaviour.

`pricing_review_required` means the rate policy requires review; `global_capacity_exhausted` means the £30 monthly ledger cannot fund the request. Neither authorises a budget increase. The database funding configuration and advisory lock remain mandatory and are not modified by a policy renewal. Roll back using the prior production deployment; after the old deadline that rollback will fail closed.

## Independent verification — 10 November 2026

OpenAI's published standard rates per million tokens are: GPT-4.1 text input $2/output $8; GPT-Image-2.5 Flare text input $5/image output $30; GPT-Image-1.5 text input $5/image output $32; GPT-Image-1 text input $5/image output $40. These match the policy rates for its supported payloads. The code rejects image input and image-edit payloads. GPT-Image-1 shut down on 23 October and is blocked by the policy; GPT-4.1 and GPT-Image-1.5 are marked deprecated. These checks do not prove model availability through the renewal window. Sources: [GPT-4.1](https://developers.openai.com/api/docs/models/gpt-4.1), [Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare), [Image 1.5](https://developers.openai.com/api/docs/models/gpt-image-1.5), [Image 1](https://developers.openai.com/api/docs/models/gpt-image-1).

The conversion reserves £1.20 per USD, equivalent to a break-even exchange rate of $0.8333/£ before any separate taxes or fees. The 10 November ECB cross-rate reported by [RateKite](https://ratekite.com/forex/gbp-usd/2026-11-10) was approximately $1.3423/£ (£0.7450/$), a reference rather than the actual card settlement rate. Actual FX, taxes, fees, model pricing, and provider spending outside this application require monitoring. The provider documentation confirms token prices but does not establish that 6,250 output tokens is a provider-enforced maximum for every permitted Flare image request; the code detects an overrun after the provider call. This remains a financial release risk to independently verify, not a guaranteed hard provider spending cap.

The cost suite passed 10/10, including the old and new expiry boundaries and seven-day warning. TypeScript and lint passed. A temporary copy of the existing ledger suite was adapted to enforce `127.0.0.1:55439` and run against disposable local PostgreSQL 18; the original remote-only guard was not changed. Thirteen synthetic scenarios passed: missing funding, concurrent final reservations, duplicate dispatch, settlement and uncertain cost retention, rollback, exhausted budget, provider-bound suspension, month rollover, mocked text/image routes, and runtime-role permissions. A fixture-only mock used a synthetic URL string to satisfy the transport-fixture guard; all actual database connections remained local and no provider calls were made. The suite's inherited `real Neon` label does not describe this local run. An initial local run failed because the synthetic fixture URL had the wrong path; after correction the complete run passed.

The previously observed production baseline was 432 passed, 10 content/hashtag failures and two skipped; the full suite was not rerun in this verification. The PR changes only this runbook, `lib/ai-cost.ts` and `tests/commercial-cost.test.mjs`; no migration, subscription, lifetime or prepaid implementation is included. The log warning is not sufficient on its own: assign an owner to check it and schedule an independent calendar review before 12 December, even when no requests occur. Alert delivery is not implemented or verified.

Release sequence, only after founder approval and the output-bound risk is accepted or resolved: review current rates, FX and provider lifecycle; verify the latest PR and passing checks; merge the maintenance PR using the authorised production workflow; observe the deployment; perform an authorised minimal synthetic text and eligible image generation, verify settlement and the unchanged budget; check logs for pricing errors and confirm subscription access.
