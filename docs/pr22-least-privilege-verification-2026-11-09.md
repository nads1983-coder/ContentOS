# PR #22 least-privilege verification preparation

9 November 2026. Final Stripe sandbox verification remains incomplete. No project-wide Vercel token or automation bypass was created during this investigation.

A ten-minute share link was created for Preview deployment `dpl_pC6WxepBvkg1aSj5kDKjLceJj4PH`. A POST using the share-link URL received HTTP 307. Stripe documents that 3xx webhook responses are failures, so that URL is not a suitable direct Stripe destination. The link was revoked.

A second short-lived link for the same deployment was used to obtain a deployment-specific session cookie. A local unsigned POST to the deployed webhook using that session reached the application, which returned HTTP 400 `Invalid signature`; it was not redirected. This establishes feasibility of a local relay for protected Preview access, but is not a Stripe delivery, signature-verification success, purchase, or end-to-end test. That link was also revoked. A future relay must restrict its listener to loopback, forward the original body and signature without logging them, keep the short-lived deployment credential out of Stripe's URL and logs, and shut down and revoke access after testing.

The official Stripe CLI v1.55.2 was downloaded to a temporary directory and checked against the publisher's SHA-256. Its test listener was attempted with the newly restricted PR22 test key; Stripe returned permission denied and identified **Debugging Tools: Write** as required. No additional permission was applied. Existing project environment access through the Vercel connector remains denied; the branch-specific owner-session editor for the authenticated diagnostic was prepared instead. The diagnostic's previous bearer was deleted during prior cleanup, so the latest Preview runtime identity and exact Stripe key remain unverified. The previous isolated database proof applies only to the earlier recorded deployment.

A fresh random diagnostic bearer was prepared in an owner-only temporary file for direct account-owner entry into the existing PR-branch Preview secret. Its value is not in this report. A subsequent Preview redeployment and an authenticated diagnostic using the independently held key digest are needed before payment tests. Stripe CLI signing secret setup and signed webhook delivery remain outstanding. Customer-facing checkout and fulfillment flags remain disabled; no payment or remote migration was run in this investigation. Previously exposed credentials still require coordinated rotation.

References: [Stripe webhook endpoint troubleshooting](https://docs.stripe.com/events/manage-webhook-endpoints), [Stripe CLI local listeners](https://docs.stripe.com/webhooks#local-listener), and [Vercel deployment share links](https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/sharable-links).
