# PR #22 Vercel environment access resolution

**Blocked, 10 November 2026.** The existing connected Vercel app returned HTTP 403 for branch-scoped project environment-variable creation and for listing project environment variables. A separate request to list integration configurations also returned 403. No denied environment operation was retried in this investigation.

The ChatGPT app permission setting for Vercel is already “Allow all actions”; that setting does not grant Vercel API scopes. In the account owner's Vercel dashboard, the active **ChatGPT** connection is identified as owned by **Vercel MCP**. Its displayed permissions cover identity, offline access, team data, and reading/changing authorised projects, deployments and domains. No environment-variable permission is displayed, and the connection's permission page has no control to add one. This supports a missing or insufficient Vercel-side authorisation as the cause of the 403; the API did not provide a more granular reason.

Vercel's documentation distinguishes integration-owned `project-env-vars` from `global-project-env-vars`, which can manage all project environment variables. The existing PR Preview variables were created under the owner's account, not established here as owned by a new integration; do not assume the narrower integration-owned scope can update them. Documentation for these scopes concerns Vercel integrations, while the observed ChatGPT connection is a Vercel MCP sign-in app, so an integration scope name must not be assumed to be an available switch for this connection. Vercel says an app developer configures its requested permissions. The owner-facing page did not offer a pending permission upgrade or a project/branch-only environment-write grant.

A supported next step is for the Vercel MCP app provider to offer a permission request for creating/updating the needed project environment variables, followed by owner consent. Before consenting, verify whether Vercel can enforce restriction to project `content-os` and Preview branch `feat/paid-creator-lifetime-2026`; the observed dashboard does not establish that branch-level restriction. If only global access is available, it would exceed the requested scope and requires a separate founder decision. An account-owner entry in the existing branch-scoped dashboard editor is another supported route, but the owner has declined to perform that entry. A project-wide access token and a deployment-wide bypass were explicitly declined and were not created.

No test diagnostic or signing secret was installed, no new deployment runtime was verified, and no new payment or migration was performed. The previously verified isolation result applies only to the earlier deployment documented in `pr22-preview-runtime-verification-2026-11-09.md`. Customer-facing sales remain disabled. Previously exposed Stripe test keys and the existing Vercel automation bypass still require coordinated rotation.
