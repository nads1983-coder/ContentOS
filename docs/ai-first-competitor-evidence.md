# AI-first competitor evidence for GetContentOS

Research accessed: **2026-10-18**. This document records public-source research. Implemented changes and separate REA observations are recorded in [the implementation report](ai-first-implementation.md).

## Decision summary

Keep the primary journey **idea -> AI-generated content pack -> editing -> save/export**, with planning downstream. The most useful documented patterns are contextual AI actions, deliberate acceptance of suggestions, reusable brand context, and persistent assets. These are interaction principles to implement independently, not interfaces or proprietary assets to copy.

**No competitor ranking is justified.** No independently verified review score, review count, review date, or comparable review cohort was collected. These products are user-selected benchmarks, not demonstrated "best-performing" or "highly rated" products. Official documentation establishes documented capabilities, not customer satisfaction or measured usability improvements.

## Method and confidence

- Sources below are public official help documentation unless explicitly marked "official product page." Read through web search/open without signing in, bypassing restrictions, or downloading competitor assets.
- "Verified evidence" means the retrieved source documents the behavior. It does not mean an authenticated workflow was executed or independently tested.
- Benefits, relevance, complexity, and priority are research judgments. GetContentOS implementation gaps must be confirmed by the main agent's repository audit; nothing here asserts that a feature is absent.
- Access dates are retrieval dates, not release dates. Search-engine crawl dates and relative "updated" labels are not reliable release evidence.
- Complexity is relative, not a delivery estimate: **S** = local UI/state using existing capabilities; **M** = API/persistence/prompt changes plus tests; **L** = new retrieval, integration, or editor infrastructure. Estimates assume existing authentication, generation, and storage can be reused.
- **P0** = core creation/control/reliability; **P1** = valuable next increment; **P2** = defer until the core journey is verified. Priorities rank proposed adaptations, not competitors.

## Recommended implementation order

The following are proposed GetContentOS behaviors and verification criteria, not claims about competitor internals or completed work.

1. **Small first-generation surface.** Show the source idea, selected output formats, active brand, and one Generate action. Put optional objective/audience/tone/length controls behind a clearly named disclosure. Do not hide usage limits, validation errors, or the active brand. Keep a non-AI path for saving unfinished ideas. Evidence anchors: Buffer assistant, Metricool generator, Jasper context rows.
2. **One pack, genuinely different outputs.** Preserve a single source brief with independent assets identified by destination and format. Keep every existing supported format. Validate format structure and limits server-side, not solely in the UI; evaluate platform suitability rather than merely varying a label. Reuse existing API/storage ownership boundaries. Evidence anchors: Jasper Canvas and Metricool configuration rows.
3. **Safe refinement.** Offer a small set of clear actions: shorten, expand, adjust tone, improve opening, improve CTA, and adapt to another format. Scope each request to a selection or asset. Propose changes separately; apply only to the revision from which they were generated. If the user edits meanwhile, retain both versions and ask them to resolve the conflict. Manual edits, copying, and ordinary downloads must not consume generation credits. Evidence anchors: Buffer, Publer, and Planable editing rows; concurrency safeguards are our engineering requirements.
4. **Reusable brand and factual context.** Carry the selected brand through initial generation and rewrites. Separate voice/style from factual notes. Show which context is in use, keep tenant authorization server-side, and bound its size. Do not claim unsupported URL ingestion: prefer pasted text/transcripts until retrieval is verified. Evidence anchors: Jasper Brand Voice, Copy.ai Infobase, Canva voice rows.
5. **Return to useful work.** Save the original idea, edited assets, chosen visuals, and pack relationship. Prefer a searchable list with status/format/brand filters before adding a complex board. Distinguish unsaved, saving, saved, and failed-save states. Export the latest edited version. Only use scheduled/published status after an actual successful operation. Evidence anchor: Buffer ideas row; save-state and publishing-truth requirements come from the brief.
6. **Optional visuals after text succeeds.** Attach generation to the selected asset, keep existing media, and allow explicit regenerate/download actions. Preserve successful text if visual generation fails. Avoid unsupported aspect-ratio promises or new paid services. Evidence anchor: Canva Magic Media row.

## Acceptance checks and measurements

- Compare the current baseline with the updated journey using the same ideas, brands, and format selections. Record required field count, user actions, time to first usable pack, generation success, saved-content retrieval, and cost per successful pack. Do not claim improvement without measurements.
- Test blank and long input, no saved brand, multiple formats, mobile viewport, keyboard-only use, and screen-reader labels. Disclosures must retain settings and expose validation errors. Contextual controls need a keyboard-accessible alternative to text selection or hover.
- Simulate partial generation failure, timeout, retry, exhausted entitlement, and navigation during a save. Preserve successful assets and source input. Retry only the failed unit when feasible, with deduplication and no duplicate usage charges under the existing billing policy.
- Test edits made while a rewrite/save request is pending; stale responses must not replace newer text. Undo must restore the actual prior version. Copy/export must reflect current edits, not the initial AI response.
- Test cross-tenant access to brand profiles, factual snippets, pack IDs, and media. No competitor privacy marketing is evidence that GetContentOS isolation is correct.
- Evaluate representative outputs for source fidelity, invented claims, repeated phrasing, brand terminology, audience fit, and destination-specific structure. Label unverified information; do not infer factual correctness from saved context alone.

- Metricool pages exposed relative update labels that varied between search and opened results. Their access date is recorded without inventing an absolute publication date. Other undated articles are not assumed new.
- No authenticated UI test, REA run, accessibility audit, performance benchmark, billing test, or empirical user study was conducted by this sidecar. These remain validation work for the main agent, not failures inferred from missing documentation.
- No external ratings were verified. No ranking, satisfaction score, market-leadership claim, guaranteed engagement lift, or guaranteed time saving is supported by this document.
- Do not adopt calendar-first navigation, mandatory social connection, extensive approval hierarchies, a new automation engine, or an infinite collaborative canvas just to match a benchmark. Retain the creation-first product identity and current entitlements.
